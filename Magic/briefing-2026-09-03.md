## Agentic Flow Ideas

> Based on repo structure, current workflow files, and Yoobin's profile as a solo co-founder building Bloggo + a personal brand in September 2026.

### 1. Automated Beta Feedback Digest Agent
- **Area:** Product / Customer Feedback
- **What to automate:** As beta users join (via TestFlight or web form), aggregate incoming feedback daily. Agent reads feedback submissions from a watched folder or form webhook, clusters them by theme (bug / UX friction / feature request / praise), ranks by frequency, and writes a `output/Research/beta-digest-[date].md` file. Surfaces the top 3 friction points to fix before launch.
- **Tool/MCP:** Claude + filesystem write + optional form webhook (Typeform, Tally) + scheduled trigger
- **Time saved:** ~3 hours/week of manual feedback review during beta period — the highest-value time save pre-launch
- **Difficulty:** Easy-Medium — cluster prompt is well-defined; the hardest part is wiring the webhook input

### 2. Content Performance Reporter
- **Area:** Content / Analytics
- **What to automate:** Weekly agent reads Instagram/TikTok analytics exports (CSV) from a watched folder, identifies which carousel type (hook type, slide count, angle) performed best, and appends a ranked performance table to `Magic/content-performance-[week].md`. Feeds directly into next week's carousel generation to prioritize high-performing angles.
- **Tool/MCP:** Claude + filesystem read/write + CSV parsing
- **Time saved:** ~2 hours/week of manual analytics review + eliminates guessing on which content works
- **Difficulty:** Easy — pure file I/O and Claude analysis; no external API needed if user exports manually

### 3. App Store Review Monitoring Agent
- **Area:** Research / Competitive Intelligence
- **What to automate:** Weekly scrape of App Store reviews for top 5 competitors (Polarsteps, Day One, Journey, Unfold, Polarsteps). Agent extracts 1-star and 2-star complaints, clusters into themes, and outputs a "Competitor Weakness Report" to `output/Research/competitor-gaps-[date].md`. Top 3 gaps feed directly into Bloggo's next marketing cycle.
- **Tool/MCP:** WebSearch + Claude + filesystem write + scheduled weekly trigger
- **Time saved:** ~4 hours/week of manual competitive research — directly informs product roadmap and copy
- **Difficulty:** Medium — App Store review scraping requires either a paid API (AppFollow, Sensor Tower) or manual paste; Claude analysis layer is straightforward

### 4. Personal Brand Scheduling Assistant
- **Area:** Content Distribution
- **What to automate:** After each morning's carousels are generated, agent reads the `.brief` sections of each HTML file, extracts the caption + hashtags + Notion destination, formats them for scheduling (Buffer or Later API), and queues the post. Also writes a `output/Content/schedule-[date].md` file showing what's queued for the week.
- **Tool/MCP:** Claude + filesystem read + Buffer API or Later API + scheduled trigger
- **Time saved:** ~5 hours/week — single largest time sink after content creation is distribution. This closes the loop on the entire content engine.
- **Difficulty:** Medium — depends on Buffer/Later API credentials; Claude parsing layer is easy

### 5. Launch Countdown Pulse Agent
- **Area:** Product / Launch Readiness
- **What to automate:** With launch approaching, agent reads the Jira ticket export (or a watched `output/UF-V1-Launch-Readiness.md` file) daily, counts open vs. closed tickets by category, and appends a "Launch Readiness Score" (% complete) to today's briefing. Flags any ticket that's been open >7 days with no activity as a blocker.
- **Tool/MCP:** Claude + filesystem read + GitHub MCP (if tickets migrate to issues) + scheduled trigger
- **Time saved:** Removes the mental overhead of "where are we vs. launch?" — the answer is always one file read away
- **Difficulty:** Easy — pure file analysis; no external API needed for the MVP version
