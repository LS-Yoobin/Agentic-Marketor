### 1. Auto-Publish Carousels via Instagram Graph API
- **Area:** Content / Distribution
- **What to automate:** `resources/instagram-api-setup.md` already documents Graph API setup, but nothing in the repo actually posts. Build an agent that screenshots each day's finished carousel HTML (Playwright is already pre-installed in this environment) and publishes/schedules the set via the Instagram Graph API — closing the loop from `output/Carousels/[date]/*.html` to a live post without manual screenshotting.
- **Tool/MCP:** Playwright (HTML→PNG) + Instagram Graph API (Meta Business), using the existing setup doc's credentials.
- **Time saved:** ~3–4 hrs/week (manual screenshot + upload + caption work for 4 carousels/day).
- **Difficulty:** Medium — Graph API setup is already documented; screenshot rendering is straightforward.

### 2. Implement the Already-Approved Trading Bot Data Layer
- **Area:** Finance / Trading
- **What to automate:** `Magic/trading-bot/docs/superpowers/specs/2026-05-27-trading-bot-design.md` is a fully approved Alpaca/Telegram trading bot spec with **zero implementation**. Today's stock-simulation run hit exactly the gap that spec would fix: there's no daily price-snapshot log, so Sharpe ratio and the 30-day graduation streak can't actually be verified (see Stock Simulation below). Build just the data-logging layer first — daily price snapshot → CSV/SQLite, computed Sharpe — before the rest of the spec.
- **Tool/MCP:** Alpaca paper trading API (already the spec's choice) + scheduled Python job + Telegram bot for approval pings.
- **Time saved:** ~2 hrs/week of manual stock research, and makes graduation analysis trustworthy instead of estimated.
- **Difficulty:** Medium — design is already approved; this is pure implementation.

### 3. Voice-to-Trip-Log Capture via Jarvis
- **Area:** Product Development / Personal Content
- **What to automate:** `jarvis/` already has `listener.py`, `transcriber.py`, `speaker.py` for always-on voice capture, currently wired for desktop tasks (Spotify, email). Repurpose the same pipeline so saying "Hey Jarvis, log this" while traveling transcribes a voice note into a timestamped trip-log entry — dogfooding Bloggo's own "blog on the go" concept for Yoobin's personal content.
- **Tool/MCP:** Existing `jarvis/listener.py` + `transcriber.py` + a new trip-log file-write tool alongside `email_tool.py`/`spotify.py`.
- **Time saved:** ~1.5 hrs/week of after-the-fact trip-memory reconstruction; captures detail that would otherwise be lost.
- **Difficulty:** Medium — transcription pipeline already built, just needs a new tool module.

### 4. App Store Review Sentiment Monitor (Bloggo's own reviews)
- **Area:** Customer Feedback / Product
- **What to automate:** Once Bloggo is live, a weekly agent pulls Bloggo's own App Store reviews, clusters complaints/praise by theme via Claude, and appends a digest to `output/Research/`. Distinct from the existing competitor-gap idea — this one watches Bloggo's **own** reviews for early signal (e.g. a rating-tanking bug) instead of competitors.
- **Tool/MCP:** App Store Connect API (post-launch) or a review scraper pre-launch + Claude analysis + filesystem write.
- **Time saved:** ~1 hr/week once live; real value is catching a problem within days instead of weeks.
- **Difficulty:** Easy once Connect API access exists; Medium if scraping is needed first.

### 5. One-to-Many Content Repurposing Pipeline
- **Area:** Content / Distribution
- **What to automate:** The 5AM carousel workflow already produces 4 HTML files daily. Run an agent right after that reads each carousel's slide copy and auto-drafts a matching TikTok/Reel voiceover script + a short LinkedIn post from the same core idea, saving to `output/Scripts/` and `output/Content/`. - **Difficulty:** Easy — no new credentials, pure Claude + file I/O on top of what already runs daily.
