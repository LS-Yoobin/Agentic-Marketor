## Agentic Flow Ideas

> Five new automation ideas for Yoobin's stack as a solo co-founder building Bloggo + personal brand. Distinct from all previous briefing sets.

### 1. Carousel Screenshot Automator
- **Area:** Content Creation
- **What to automate:** After the morning carousel generator saves 4 HTML files, a headless Playwright agent opens each `.html` file in Chromium, screenshots every `.slide` div at exactly 360×450px, saves each as a numbered PNG (`slide-01.png`, `slide-02.png`...), and zips the set into a folder ready for Instagram upload. Removes the manual screenshot step entirely.
- **Tool/MCP:** Playwright (pre-installed in the Agentic-Marketor environment) + Node.js script + filesystem write
- **Time saved:** ~20 minutes/day of manual screenshotting — 2.3 hours/week
- **Difficulty:** Easy — Playwright is already available; the script just needs a glob over the output directory and a loop over `.slide` elements

### 2. App Store Review Alert Agent
- **Area:** Product / Customer Feedback
- **What to automate:** A weekly agent that checks for new Bloggo App Store reviews (via App Store Connect API or Appbot), extracts the text of any 1–3 star reviews, clusters them by theme (crash / missing feature / confusing UI / pricing), and writes a ranked "This Week's Pain Points" summary to `output/Research/app-store-pain-[date].md`. The best 1-star reviews also get flagged as content ideas in `docs/Marketing/Idea Inbox.md`.
- **Tool/MCP:** App Store Connect API + Claude analysis + filesystem write
- **Time saved:** ~2 hours/week of manual review reading and triaging
- **Difficulty:** Medium — App Store Connect API requires key setup; Claude analysis layer is straightforward

### 3. Weekly Revenue / Metrics Snapshot Agent
- **Area:** Finance / Business Tracking
- **What to automate:** Every Sunday, agent pulls Bloggo's download count and any revenue data from App Store Connect, formats it as a plain-English "Week in Numbers" block, and appends it to a running `Magic/metrics-log.md`. Over time this builds a compounding record of growth that also feeds building-in-public content. Agent also generates a tweetable "week in numbers" draft.
- **Tool/MCP:** App Store Connect API + filesystem write + Claude formatting
- **Time saved:** ~1 hour/week of manual metric logging; also creates automatic content fodder
- **Difficulty:** Medium — same API key as idea #2; metrics formatting is easy once connected

### 4. Link-in-Bio Auto-Updater
- **Area:** Content Distribution
- **What to automate:** When a new carousel set is generated each morning, agent checks today's date, selects the highest-priority carousel from the brief metadata, and updates the Linktree (or Beacons) bio link to point directly to the Bloggo beta signup. If a carousel is a Yoobin personal post, it updates the Yoobin link; if Bloggo, the Bloggo link. No manual bio editing needed after each post.
- **Tool/MCP:** Linktree API or Beacons API + filesystem read (carousel brief metadata) + Claude decision layer
- **Time saved:** ~10 min/day = 1.2 hours/week (small but eliminates a consistent point of friction)
- **Difficulty:** Easy-Medium — depends on whether Linktree/Beacons exposes an API; Beacons.ai does

### 5. Trip Backlog Audit Agent (Eat Your Own Dog Food)
- **Area:** Personal Productivity / Product Research
- **What to automate:** A monthly agent that asks Yoobin for photo count of top 5 unprocessed trips, generates a "Camera Roll Audit" report showing how many trips have no blog yet, and creates 5 content hooks from those specific trip names/locations. Serves dual purpose: forces Yoobin to use Bloggo on his own backlog (authentic product demo content) AND generates hyper-specific content ideas grounded in real trips rather than generic hooks.
- **Tool/MCP:** Manual input prompt → Claude analysis → filesystem write to `docs/Marketing/Idea Inbox.md`
- **Time saved:** ~30 min/month of brainstorming; more importantly, generates the most authentic content type (founder using their own product on real trips)
- **Difficulty:** Easy — pure Claude analysis task; no API integration needed beyond conversation input
